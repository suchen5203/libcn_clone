# 数据文件格式 (DATA_FORMAT)

## 1. `libdlc.data` —— 插件主配置

### 1.1 总体布局

```
偏移 0          ┌──────────────────────┐
                │  Header (12 B)        │  ←  dlc_header_t
偏移 12         ├──────────────────────┤
                │  Table A (1140 B)     │  ←  57 × 20 B = dlc_table_a_t
偏移 1152       ├──────────────────────┤
                │  Table B (504 B)      │  ←  21 × 24 B = dlc_table_b_t (估计)
偏移 1656       ├──────────────────────┤
                │  Main Body (~20.7 MB) │  ←  ~41K 条 ~500B 记录
偏移 ~20.7MB    ├──────────────────────┤
                │  Zero Padding (~9.3MB)│  ←  0x00 填充到 30MB
偏移 30MB       └──────────────────────┘
```

### 1.2 Header(12 B)

| 偏移 | 类型 | 字段 | 说明 |
|------|------|------|------|
| 0 | u32 | `version` | 文件版本,本克隆用 `57` 匹配原版默认 |
| 4 | u32 | `count_a` | 表 A 记录数,本克隆写死 `57` |
| 8 | u32 | `reserved` | 必须为 `0` |

### 1.3 Table A —— 概率/掉率曲线(每条 20 B)

| 偏移 | 类型 | 字段 | 说明 |
|------|------|------|------|
| 0 | f32 | `f1` | 主参数(随 id 递减,如 0.7→0.15) |
| 4 | i32 | `pad1` | 必须为 0 |
| 8 | i32 | `pad2` | 必须为 0 |
| 12 | f32 | `f2` | 次参数(随 id 递增,如 0.3→0.85) |
| 16 | u32 | `id` | 记录 id(1..57) |

默认样例(由逆向报告提取):

| id | f1 | f2 |
|----|------|------|
| 1 | 0.700 | 0.301 |
| 2 | 0.600 | 0.401 |
| 3 | 0.500 | 0.501 |
| ... | ... | ... |
| 57 | 0.150 | 0.851 |

> 语义推测:HP/MP 倍率 / 掉率曲线。`f1` 可能对应"基础倍率",`f2` 对应"加成概率"。

### 1.4 Table B —— ± 对称参数表(每条 24 B)

| 偏移 | 类型 | 字段 | 说明 |
|------|------|------|------|
| 0 | u32 | `id` | 记录 id |
| 4 | f32 | `neg` | 负向参数 |
| 8 | f32 | `pos` | 正向参数 |
| 12 | i32 | `pad` | 必须为 0 |
| 16 | f32 | `const_1001` | 常数 `1.001`(版本/缩放系数) |
| 20 | u32 | `next_id` | 链表下一条 id(可能为空) |

示例:

| id | neg | pos |
|----|------|------|
| 22 | -0.500 | 0.500 |
| 23 | -0.550 | 0.550 |
| 24 | -0.600 | 0.600 |

### 1.5 Main Body(每条 ~500 B)

非零双字间隔直方图显示记录粒度约 480–504 B(峰值 ~494),每条约含 2 个非零双字(`id` + `value`)。约 4.1 万条。

本克隆的简化定义(填零到 500 B 槽位):

```c
typedef struct {
    uint32_t id;        // 偏移 0
    float    value;     // 偏移 4
    uint8_t  pad[492];  // 偏移 8..499(填 0)
} dlc_main_entry_t;
```

### 1.6 Zero Padding

文件总大小固定为 **30 MB**(30,720,000 字节)。Main Body 之后到 EOF 全部填 0x00。

## 2. `resource.data` —— 加密资源包

### 2.1 总体

固定大小 **65,535 字节**(0xFFFF)。明文分四段后整体加密。

### 2.2 明文结构(加密前)

```
┌──────────────────────────────────────────────────────┐
│  Magic "DLCr" (4B)                                   │
│  Section count = 4 (u32)                             │
│  ┌──────────────────────────────────────────────┐    │
│  │  Section 0: aipolicy                          │    │
│  │    [u32 name_len][name][u32 data_len][data]    │    │
│  ├──────────────────────────────────────────────┤    │
│  │  Section 1: elements                          │    │
│  │    ...                                        │    │
│  ├──────────────────────────────────────────────┤    │
│  │  Section 2: gshop                             │    │
│  ├──────────────────────────────────────────────┤    │
│  │  Section 3: tasks                             │    │
│  └──────────────────────────────────────────────┘    │
└──────────────────────────────────────────────────────┘
```

每节:

| 字段 | 大小 | 说明 |
|------|------|------|
| `name_len` | u32 | section 名长度(含 NUL) |
| `name` | 变长 | section 名,如 `aipolicy.data` |
| `data_len` | u32 | 原文长度 |
| `data` | 变长 | 原文 |

### 2.3 加密方案

默认 **AES-128-CBC**:
- 密钥:16 字节,运行时从配置文件/环境变量读取
- IV:16 字节,文件首 16 字节明文存 IV
- 填充:PKCS#7

资源加载流程:
```
读 resource.data
  └─► IV = data[0..15]
      ciphertext = data[16..]
      plaintext = AES-128-CBC-decrypt(key, IV, ciphertext)
        └─► 按 "DLCr" 头 + 4 sections 解析
```

⚠️ **密钥不可硬编码到 .so 里**(原版也是从外部配置读)。本克隆默认从 `./libcn.key` 读 16 字节密钥。

## 3. KEY 文件 `libcn.key`

明文 16 字节二进制,与 `libcn_clone.so` 同目录。`keycheck.c` 默认空校验,可改为:
- 与硬编码 HASH 比对
- 调远程 HTTP 服务
- RSA 签名校验

## 5. `res/*.data` 源文件

四份源数据格式继承自原 PW 私有服务端(完美世界 GNET),各自有自定义 schema。本克隆**不重写四份格式**(那是游戏数据,需要原版样本/文档对照)。

编辑器阶段,四份源文件按字节级原样切片打包进 `resource.data`。运行时由 `libcn.so` 按同名 `[aipolicy.data` 标记定位还原。
